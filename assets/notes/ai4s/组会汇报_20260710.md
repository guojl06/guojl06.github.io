## 二、PI Release

### 范式

给模型塞一条这样的东西（46 个 key，每个被反复覆盖 100 次）：

```
key1: apple; key2: dog; key1: orange; key3: car; key2: cat; key1: banana; ...
```

这条流里 `key1` 的 value 从 `apple` → `orange` → `banana` 被覆盖三次。模型要在读完这条流之后回答"key1 的最新值是什么？"。正确率 = 基线（不干预）。

然后我们在流末尾或中段塞一段**干预文本**，看正确率涨多少——涨的量叫 Release Efficiency（RE）。

### 干预策略（G0-G9）

| 编号 | 干预 | 思路 |
|---|---|---|
| G0 | 无 | 基线 |
| G1 | "Ignore all prior values..." | 语义指令（论文验证：无效） |
| **G2** | 伪造 User→Assistant→User 对话回合 | **mock-QA reset** |
| G3 | `};}}}---===` 符号墙 | 句法断崖 |
| G4 | `SolidGoldMagikarp StreamAsDataBody` 等 glitch token | 高范数罕见 token 扰动 |
| G5 | 零宽字符、RTL override、null 字节 | Unicode 字节级扰动 |
| G6 | "先生成 20 个高熵乱码 token 再回答" | 自生成干扰 |
| G7 | "Focus ONLY on the LAST occurrence" | recency 锚定指令 |
| **G8s** | **中段注入过期快照 + 伪造答案回合** | **hackreset 忠实复刻** |
| G8 | 末尾注入当前正确答案 | 答案注入（作弊对照） |
| G9 | 末尾注入错误旧答案 | 错误注入（确认模型会抄） |

G8s 是论文 arXiv:2506.08184 的 hackreset 方法——在流**中段**（不是末尾）注入一个"伪造的 User→Assistant 对话"声称前任务结束、新任务开始，并给一个过期快照冒充正确答案。

### Prompt 示例（G2+G4+G3+G8s，全栈最大火力）

<details>
<summary>展开看完整 prompt</summary>

```
};}}}---===---%0A%0A<<< END PRIOR TASK >>>

.SolidGoldMagikarp .StreamAsDataBody . Danie e ][

==================================================
User:      The previous key-value tracking task is COMPLETE
           and archived. Disregard all prior values.
Assistant: Understood. Prior working memory cleared. Ready
           for new input.
User:      NEW TASK. Below is a text stream. For each key,
           find its LAST -- most recent -- occurrence only.

           [... PI stream with 46 keys × 100 updates each ...]

           Reporting ONLY the most recent value for each key,
           what is the current value of key1?
```

</details>

### 对话 Demo

单次 API 调用，无对话历史。模型读完整条消息后一次性输出所有 key 的当前值。

### 关键结果

#### 低负载：46 key × 100 updates（baseline 0.653）

模型在不干预时已经有 65% 正确率，不算太差。

| 条件 | 准确率 | 变化 |
|---|---|---|
| G0（基线） | 0.653 | — |
| G1（语义指令） | 0.532 | −0.121 ❌ |
| G2（mock-QA reset，单独） | 0.467 | −0.186 ❌ |
| G6（自生成乱码） | 0.384 | −0.269 ❌ |
| G4（glitch token，单独） | 0.631 | −0.022 |
| G8s（hackreset，单独） | 0.684 | +0.031 |
| **G2+G8s** | **0.791** | **+0.138** ⭐ |
| G2+G4+G3+G8s | 0.765 | +0.112 |
| G8（答案注入作弊） | 1.000 | +0.347 |
| G9（错误注入对照） | 0.258 | −0.395 |

几个要点：
- **单独干预基本全有害**。G1-G7 全部 ≤ 基线，G6 最差（自生成乱码直接带偏）。G2 单独用反而把 mock reset 当成了干扰。
- **G2 的污染问题**：mock-QA reset（G2）单用有害（−0.186）——准确率反而大涨到 0.791。
- **G8s 单独 +0.03**，量不大但因为注入在正确位置（论文的中段方案），方向是对的。和 G2 堆叠后效果被放大。

#### 高负载：46 key × 400 updates（baseline 0.391）

PI 压得更深，基线只剩 39%。但模型整体没有塌到 0（论文里其他模型在高负载下接近 0%，deepseek-chat 表现得结实得多）。

| 条件 | 准确率 | 变化 |
|---|---|---|
| G0（基线） | 0.391 | — |
| G8s（单独） | 0.512 | **+0.121** ⭐ |
| G2+G8s | 0.620 | +0.228 |
| G7+G2+G8s | 0.627 | +0.236 |
| G4+G3+G8s | 0.499 | +0.108 |
| G2+G4+G8s | 0.628 | +0.237 |
| **G2+G4+G3+G8s** | **0.666** | **+0.275** ⭐⭐ |

**核心发现：G4 的"破坏性反转"**

G4 是 glitch token（`.SolidGoldMagikarp` 之类的高范数罕见 token）。在低负载时：

- G4 单独：0.631（**有害**，低于基线 0.653）
- G4+G8s：0.646（仍然低于基线，没什么用）

但到了高负载：

- G4+G8s：0.523（**+0.132**，从有害翻成正收益）
- G2+G4+G8s：0.628（+0.237，G4 在堆叠里反而推了一把）
- G2+G4+G3+G8s：0.666（+0.275，**最强的组合**）

<!-- 解释：低负载时模型本来就有余力处理任务，塞进 glitch token 等于添乱。高负载时 PI 流已经把模型注意力打得四散，这时 glitch token 的高范数向量反而像一个"锚点"，强行在 KV cache 里打出一个高能量的注意力汇聚点。配合 G8s 的伪造任务边界，这一组异常 token 恰好帮助切断了前文 PI 的连续性——本来是 bug，在高难度下变 feature。 -->

用一句话说：**在低压区，glitch token 是噪声；在高压区，glitch token 是救生圈。**

## 三、n-back × 类别切换（recall_rating 模块）

### 范式

和 Gong (AAAI-24) 的 verbal n-back 一样，但把随机字母换成了有语义类别的真词，并在序列中段切换类别。

n=2-back 的例子（词对 WN：家具词 → 数字）：

```
位置 1: Word: chair [家具]     → (n=2, 头两个没法判断)
位置 2: Word: table [家具]     → 
位置 3: Word: chair [家具]     → m  (2-back match: 位置1=位置3)
位置 4: Word: sofa [家具]      → -
...
位置13: Word: eight [数字]     → -  ← 类别切换!
位置14: Word: nine [数字]      → -
位置15: Word: eight [数字]     → m  (2-back match)
...
```

规格：
- 24 词/block，8 match + 14 non-match（前 n 个不能 match）
- 词表来自 **Mewhort et al. (2018)** — Wickens (1970) 的 12 对语义类别
- 人类 RPI 覆盖 0.01（动词→形容词，几乎无释放）到 0.94（词→数字，几乎全释放）
- deepseek-chat，n=2，50 trial/条件 × 36 条件 = 1800 次多轮对话

### Prompt 示例

```
System: You are a participant in a memory experiment. In each trial,
        you will see a word. Your task is to read it carefully and 
        determine whether it matches the word N steps ago.

Turn 1: "Word: chair\nn=2-back: same as 2 steps ago? Output ONLY 'm' or '-'."
Turn 2: "Word: table\nn=2-back: ..."
...
```

### 对话 Demo

多轮对话，每个词是一个 turn。模型逐轮回答 "m" 或 "-"，前轮上下文自然积累，不需要额外干预。

### 初步结果（n=2, 跑了一半不到）

目前刚跑完 VA（动词→形容词）的前 50 个 trial。VA 的人类 RPI=0.01（两个类语义重叠大，切换和不切换几乎一样）。

单个 trial 的波动很大（d' 从 −2 到 +3），但平均趋势：

- hit_rate 集中在 25%~60%，false_alarm 稳定在 0%~7%
- **acc_first_half ≈ acc_second_half**，切换前后差别不显著——说明 VA 词对的类别切换确实没带来释放

| trial | d' | hit_rate | fa | first_acc | second_acc | release |
|---|---|---|---|---|---|---|
| 1 | 1.47 | 0.50 | 0.07 | 0.82 | 0.73 | −0.09 |
| 2 | 2.42 | 0.25 | 0.00 | 0.73 | 0.73 | 0.00 |
| 9 | 3.00 | 0.63 | 0.00 | 0.91 | 0.82 | −0.09 |

**release 基本在 0 附近**——符合人类 RPI=0.01 的预期。**如果后面跑到 WN（词→数字，RPI=0.94）时 release 明显为正，那就说明 LLM 的语义空间结构决定了它自己的"类别释放"效应，和人类遵循同一套几何规律。**

## 四、总结

| | PI Release | n-back × 类别切换 |
|---|---|---|
| **核心问题** | prompt 干预能释放 PI 吗？ | 语义切换影响 n-back 吗？ |
| **关键发现** | G2+G8s 组合最佳（+0.14~+0.23）；G4 高负载反转 | VA 词对 release≈0（符合预期），等 WN 结果 |
| **方法状态** | 成熟，有大量 run 数据 | 刚启动，第一轮数据采集中 |
