# 架构设计：探索副本系统

刷新

在 RPG 游戏中，角色进入副本前可以携带一种武器和一种工具。不同装备会影响探索收益，不同副本也会在进入时对玩家状态产生影响。为了保证系统具有良好的可扩展性，现请你使用面向对象设计思想，实现一个“探索副本系统”。

### 系统需求

#### 玩家与装备

玩家拥有一种武器和一种工具。武器会根据副本难度计算武器分数，且可能在探索过程中被强化；工具会提供固定工具分数。玩家只会在创建时选择装备，之后无法更换或获得新的装备。

玩家探索副本时，会根据副本难度 `level` 计算武器分数和工具分数，并最终得到奖励。

武器类型如下：

-   剑：具有属性 `power`，类型为浮点数。武器分数为 `power - level`。被强化时，`power = power * 1.05`。
-   法杖：具有属性 `magic`，类型为浮点数。如果 `level > magic`，武器分数为 `0`；否则武器分数为 `magic / 2.0`。被强化时，`magic = magic * 1.1`。
-   匕首：创建时不需要额外数值。武器分数为 `level`。武器强化对匕首不产生效果。

工具类型如下：

-   火炬：工具分数为 `3`
-   探测器：工具分数为 `6`
-   工具包：工具分数为 `9`

有的副本会封印工具，这会使玩家失去装备的工具；此后工具分数为 `-1`。

题目保证创建玩家时传入的武器名称和工具名称均合法。

#### 副本

游戏中存在三种类型的副本：普通副本、工具封印副本和武器强化副本。每个副本都有一个难度 `level`，类型为整数。玩家进入副本时，副本会根据自身类型对玩家状态产生不同影响，并根据玩家当前装备计算最终奖励。

##### 普通副本

-   进入副本时，输出 `Enter dungeon, level: X`，其中 `X` 为副本难度。
-   奖励计算方式为 `武器分数 + 工具分数`。

##### 工具封印副本

-   进入副本时，封印玩家的工具，这也会影响后续副本探索。
-   输出 `Enter tool seal dungeon, tool disabled, level: X`，其中 `X` 为副本难度。
-   奖励计算方式为 `(武器分数 + 工具分数) * 2`。

##### 武器强化副本

-   进入副本时，强化玩家的武器，这也会影响后续副本探索。
-   输出 `Enter weapon enhance dungeon, weapon enhanced, level: X`，其中 `X` 为副本难度。
-   奖励计算方式为 `武器分数 + 工具分数`。

### 接口约定

**`Player* createPlayer(std::string weaponName, float weaponValue, std::string toolName);`**

-   `weaponName` 表示武器类型，保证为 `"sword"`、`"staff"` 或 `"dagger"` 中的一种，分别对应剑、法杖和匕首。
-   `weaponValue` 表示武器的初始数值，剑对应 `power`，法杖对应 `magic`，匕首不需要该数值但仍会传入一个浮点数（可以忽略）。
-   `toolName` 表示工具类型，保证为 `"torch"`、`"detector"` 或 `"toolkit"` 中的一种，分别对应火炬、探测器和工具包。

**`Dungeon* createDungeon(std::string dungeonName, int level);`**

-   `dungeonName` 表示副本类型，保证为 `"normal"`、`"toolseal"` 或 `"weaponenhance"` 中的一种，分别对应普通副本、工具封印副本和武器强化副本。
-   `level` 表示副本难度，为一个整数。

**`float Dungeon::startExplore(Player* player)`**

-   调用该函数，副本会根据玩家当前装备状态计算奖励并返回。

你不需要修改上述接口，也无需关心其具体实现。

### 样例解释

我们下发了一个样例 `main.cpp` ，以及包含了上述约定接口的 `ExploreSystem.h` ，其中 `main.cpp` 如下

```
#include "ExploreSystem.h"

#include <iomanip>
#include <iostream>

void test_sample1() {
    std::cout << "Test Sample 1:" << std::endl;

    Player* player = createPlayer("sword", 20, "torch");
    Dungeon* dungeon = createDungeon("normal", 5);

    float reward = dungeon->startExplore(player);
    std::cout << "Reward: " << reward << std::endl;

    delete player;
    delete dungeon;
}

void test_sample2() {
    std::cout << "Test Sample 2:" << std::endl;

    Player* player = createPlayer("staff", 8, "torch");
    Dungeon* dungeon = createDungeon("weaponenhance", 10);

    for (int i = 0; i < 4; i++) {
        float reward = dungeon->startExplore(player);
        std::cout << "Round " << i << " reward: " << reward << std::endl;
    }

    delete player;
    delete dungeon;
}

int main() {
    std::cout << std::fixed << std::setprecision(2);
    test_sample1();
    test_sample2();
    return 0;
}

```


在 `test_sample1` 中，玩家装备剑和火炬，进入难度 `level = 5` 的普通副本。

计算过程如下：

1.  剑的初始 `power = 20`
2.  武器分数为 `20 - 5 = 15`
3.  火炬的工具分数为 `3`
4.  普通副本奖励为 `15 + 3 = 18`

因此输出奖励为 `18.00`。

在 `test_sample2` 中，玩家装备法杖和火炬，连续 4 次进入同一个难度 `level = 10` 的武器强化副本。

火炬的工具分数始终为 `3`。每次进入武器强化副本时，法杖的 `magic` 都会乘以 `1.1`。

计算过程如下：

1.  初始 `magic = 8`
2.  第 0 次进入后，`magic = 8 * 1.1 = 8.8`，仍小于 `level = 10`，武器分数为 `0`，奖励为 `0 + 3 = 3`
3.  第 1 次进入后，`magic = 8.8 * 1.1 = 9.68`，仍小于 `level = 10`，武器分数为 `0`，奖励为 `3`
4.  第 2 次进入后，`magic = 9.68 * 1.1 = 10.648`，已经不小于 `level = 10`，武器分数为 `10.648 / 2.0 = 5.324`，奖励为 `5.324 + 3 = 8.324`，保留两位小数输出 `8.32`
5.  第 3 次进入后，`magic = 10.648 * 1.1 = 11.7128`，武器分数为 `11.7128 / 2.0 = 5.8564`，奖励为 `5.8564 + 3 = 8.8564`，保留两位小数输出 `8.86`
